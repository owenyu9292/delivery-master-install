# 배송마스터 현재 운영 규칙

> 이 문서가 과거 작업 기록보다 우선합니다. 과거 PWA·USB·GitHub Pages 문구는 당시 기록이며 현재 배포 규칙이 아닙니다.

## 제품과 보호 범위

- 정식 제품과 유일한 수정 대상은 Android 인스톨 앱이다.
- 실제 작업 저장소는 `C:\Codex55Workspace\delivery-master\delivery-master-install-deploy`이다.
- PWA v1과 `season2`는 보관용 원본이다. 명시 승인 없이는 수정·빌드·배포하지 않는다.
- 기존 PWA 개발앱 게시본도 원본 보관 대상이다. 현재 수정·검수 기준은 인스톨 버전이며, 소스 변경을 PWA 게시 파일에 자동 반영하지 않는다.

## 힐스 별도 작업 시간

- 반품·선집화·상차는 기존 정리와 별개의 시간이다. 기본 제안값 30분을 직접 수정하고 명시적으로 기록한다. 자동 적용하지 않는다.
- 전체 업무 경과와 수량은 그대로 두고, 배송 효율 계산 시간에서만 기존 정리에 추가로 차감한다.
- 같은 구역의 기록 버튼을 여러 번 눌러도 하나의 timeline incident를 갱신한다. 취소는 0분으로 남겨 이력을 보존하고 다시 적용할 수 있다.
- 완료 후에는 로그의 작업시간 연필로 재수정한다. 빠뜨린 경우 힐스 완료 로그의 연필에서 소요분을 추가한다.
- 정리나 별도 이벤트에 이미 기록한 동일 작업을 다시 입력하지 않는다. 이 기능은 별개로 소비한 시간의 합계다.

## 하위 작업자

- 범위가 분리 가능한 조사, 문서 대조, 테스트, 보조 구현은 **루나**를 우선 사용한다.
- 코기는 작업 분배, 병합, 전체 검수, 커밋, GitHub 업로드와 최종 보고를 맡는다.
- 루나 결과만으로 코드·문서·배포를 완료 처리하지 않는다. 코기가 반드시 현재 소스와 결과를 대조한다.
- 루나를 호출할 수 없거나 작업이 너무 작아 단독 처리한 경우, 사유를 작업 기록에 남긴다.

## 배포와 설치

- 이후 정식 앱 배포는 **GitHub APK 다운로드·업데이트 설치**만 사용한다.
- 사용자에게 APK를 전달할 때는 직접 APK/raw 링크가 아니라 **GitHub Release 페이지 링크**를 제공한다. 폰에서는 Release 페이지의 Assets에서 APK를 누르게 안내한다.
- 현재 v35 Release 페이지는 https://github.com/owenyu9292/delivery-master-install/releases/tag/v35 이다. Assets의 DeliveryMaster-v35-debug.apk를 기존 앱 삭제 없이 업데이트 설치한다.
- USB/ADB는 실기기 검수 또는 긴급 진단용이며, 일반 사용자 배포 경로가 아니다.
- GitHub 업로드 전에는 코드 검사, 빌드, 문서·APK 버전·해시 대조를 완료한다.
- 기존 앱 삭제 없이 같은 package ID와 서명을 유지한 APK로 업데이트 설치한다.

## 승인과 핫픽스

- 일반 수정, 커밋, GitHub 업로드는 작업 범위를 보고하고 승인받은 뒤 진행한다.
- 현장 핫픽스의 예외 범위와 후속 정식 반영은 `HOTFIX_HANDOFF.md`를 따른다.
- 중요한 규칙 변경은 이 문서와 작업 보드에 함께 기록한다.

## 추가구역 오입력 복구

- 대체배송·추가구역을 잘못 추가했더라도 시작 로그만 있는 동안에는 잘못 추가함 · 취소로 즉시 이전 단계로 돌아갈 수 있어야 한다.
- 취소 전에는 해당 날짜의 내부 안전 스냅샷을 저장한다.
- 정리, 배송, 수량, 이벤트, 도우미 기록이 하나라도 생긴 구역은 단순 삭제하지 않는다. 이 경우 기록 정정 경로를 사용한다.
- 배포 전에는 종료 직전 오입력, 중간 취소 후 재추가, 반복 대체배송, 기록 발생 후 취소 차단을 실제 모바일 화면에서 검수한다.
## 파일 저장과 복구
- 오류를 막는 것과 복구하는 것을 함께 검수한다. 저장 실패 전후 전체 날짜 기록 비교, 입력 초안 유지, 재시도 성공, 두 번 누름을 포함한다.
- 여러 날짜를 가져오다 실패하면 해당 가져오기 전체를 취소한다. 기록 반영 뒤 후속 스냅샷만 실패했을 때는 실제 반영 건수를 숨기거나 0일로 보고하지 않는다.
- 손상된 기록을 읽지 못해도 빈 날짜로 덮어쓰지 않는다. 안전 보관과 유효한 백업 복구 경로를 제공한다.
- 로그 시간 정정은 계속 허용하되, 시간이 역전되거나 확인 불가하면 효율을 미확정으로 표시한다. 수량과 기존 원문은 유지한다.
- 수동 내보내기는 Android 시스템 파일 저장창을 사용한다. 공유 앱 선택창은 저장 성공이 아니다.
- 가져오기는 Android 시스템 문서 선택창을 사용하고 선택한 JSON을 구조 검증한 뒤 적용한다.
- 기존 날짜는 명시적 승인 없이 덮어쓰지 않는다. 보존 선택 시 기존 날짜를 건너뛰고 없는 날짜만 가져온다.
- 업무 종료와 위험 작업 전후 스냅샷은 앱 내부에 보관하고 최신 5개를 유지한다.
- 배포 전 검증은 정상 선택, 취소, 손상 JSON, 중복 날짜, 기존 날짜 보존, SQLite 재조회까지 포함한다.
- 가져오기 결과가 `0일`이어도 모든 날짜가 이미 존재하고 보존 모드를 선택했다면 정상이다. 이때 기존 날짜는 건너뛰고 데이터는 덮어쓰지 않는다.
